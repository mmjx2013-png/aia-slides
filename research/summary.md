## 2. ความปลอดภัย (HTTP headers)

ใช้คำสั่ง `curl -sI <url>` กับหน้าแรก (ผลดิบอยู่ใน `headers/`)

| Header / การตั้งค่า | เว็บเก่า | เว็บใหม่ |
|---|---|---|
| `Server` | `Apache/2.4.52 (FreeBSD) OpenSSL/1.1.1a-freebsd PHP/7.3.33` (บอกชื่อและเวอร์ชันซอฟต์แวร์ครบ) | `GitHub.com` |
| `X-Powered-By` | `PHP/7.3.33` | ไม่มี |
| `Strict-Transport-Security` (บังคับ HTTPS) | **ไม่มี** | `max-age=31556952` (1 ปี) |
| `Content-Security-Policy` | ไม่มี | ไม่มี (GitHub Pages ตั้ง header นี้เองไม่ได้ ใส่เป็น `<meta>` ในหน้าได้) |
| `X-Frame-Options` | ไม่มี | ไม่มี |
| `X-Content-Type-Options` | ไม่มี | ไม่มี |
| เปิดด้วย `http://` (ไม่เข้ารหัส) | **ได้หน้าเว็บ (200) ไม่ส่งต่อไป https** | ส่งต่อไป https (301) |

ซอฟต์แวร์ที่เว็บเก่าประกาศว่าใช้อยู่:
- **PHP 7.3** หมดการดูแล (End of Life) ตั้งแต่ 6 ธ.ค. 2021 ไม่มีแพตช์ความปลอดภัยมาเกือบ 5 ปี (ที่มา: https://www.php.net/eol.php)
- **OpenSSL 1.1.1** หมดการดูแลตั้งแต่ 11 ก.ย. 2023 และตัวที่ใช้คือ 1.1.1**a** ซึ่งเป็นรุ่นย่อยแรกของสาย 1.1.1 (ที่มา: https://openssl-library.org/post/2023-09-11-eol-111/)
- Apache 2.4.52 ขณะที่หน้าแรกของ https://httpd.apache.org/ ประกาศรุ่น 2.4.71 แล้ว (ตรวจวันที่ 25 พ.ย. 2026)
- HTML ของเว็บเก่าบอกเวอร์ชันปลั๊กอิน WordPress ด้วย: All in One SEO 4.5.5, WordPress Download Manager 3.2.84

ข้อดีของเว็บเก่าที่ควรพูดอย่างเป็นธรรม: มีไฟร์วอลล์ที่บล็อกเบราว์เซอร์อัตโนมัติแบบ headless (เจอตอนแคปหน้าจอ ดูหัวข้อ 4)

ข้อควรระวังเวลาพูด: การที่ header บอกเวอร์ชันเก่า **ไม่ได้แปลว่าเว็บถูกเจาะแล้ว** แค่แปลว่าเสี่ยงกว่าและผู้โจมตีรู้ว่าจะลองช่องโหว่ไหน ไม่ได้ทดสอบเจาะระบบใดๆ

ที่มา: `headers/old-home.txt`, `old-home-http.txt`, `new-home.txt`, `new-home-http.txt`

## 3. ต้องกดกี่ครั้งถึงเจอข้อมูล (นับจากหน้าแรก)

นับเฉพาะการคลิกหรือแตะ ไม่นับการเลื่อนหน้า แต่บอกระยะที่ต้องเลื่อนไว้ด้วย (1 จอ = 900px บนคอม, 844px บนมือถือ)
ทดสอบในเบราว์เซอร์จริงที่ขนาด 1440×900 และ 390×844

| ข้อมูล | เว็บเก่า: คอม | เว็บเก่า: มือถือ | เว็บใหม่: คอม | เว็บใหม่: มือถือ |
|---|---|---|---|---|
| **รับสมัคร** | **1 คลิก** แต่ต้องรู้ว่าอยู่ใต้เมนู "สำหรับผู้ปกครองและบุคคลทั่วไป" (ชี้เมนูแล้วกด "ใบสมัครรับนักเรียน…") | **3 แตะ** (☰ → สำหรับผู้ปกครองฯ → ใบสมัครรับนักเรียน…) | **1 คลิก** (เมนู "รับสมัคร" หรือปุ่ม "สมัครเรียน" บนแถบหัว) | **1 แตะ** (ปุ่ม "ข้อมูลการรับสมัคร" ในจอแรก) |
| **เบอร์โทร** | **0** (อยู่บนหัวเว็บ) | **0 แตะ แต่ต้องเลื่อนลงท้ายหน้า ≈ 6,200px (ประมาณ 7 จอ)** หรือ 2 แตะ (☰ → ติดต่อเรา) | **0** (การ์ด "ติดต่อโรงเรียน" ขอบล่างของจอแรก) | 0 แตะ แต่ต้องเลื่อน ≈ 3,060px (ประมาณ 3.6 จอ) หรือ **1 แตะ** (การ์ด "ติดต่อโรงเรียน" ขอบล่างจอแรก → หน้าติดต่อ) |

| **แผนที่** | 0 คลิก แต่ต้องเลื่อน ≈ 3,100px (ประมาณ 3.5 จอ) หรือ 1 คลิก (เมนู "ติดต่อเรา") | 0 แตะ แต่ต้องเลื่อน ≈ 5,500px (ประมาณ 6.5 จอ) หรือ 2 แตะ (☰ → ติดต่อเรา) | **1 คลิก** (เมนู "ติดต่อ" → หน้าติดต่อมีแผนที่ Google Maps) | **1 แตะ** (การ์ด "ติดต่อโรงเรียน" ในจอแรก → หน้าติดต่อมีแผนที่) |

หมายเหตุ:
- หน้าแรกเว็บเก่ามีโปสเตอร์รับสมัครในสไลด์โชว์ แต่เป็นรูปภาพ (ต้องสแกน QR) และลิงก์ในสไลด์โชว์ไปที่เพจ Facebook ไม่ใช่หน้ารับสมัครบนเว็บ
- บนมือถือ เว็บเก่าซ่อนเบอร์บนหัวเว็บ เหลือเพียงปุ่ม ☰
- บนมือถือ เว็บใหม่ก็ซ่อนเบอร์ในการ์ด "ติดต่อโรงเรียน" (`small.th` เป็น `display:none`) ถ้าแสดงเบอร์ในการ์ดนี้ หรือทำให้การ์ดกดโทรได้เลย จะเหลือ 0 แตะ

### ที่ยังขาด: ภาพเว็บเก่าขนาดคอม (1440×900)

ต้องแคปด้วยมือใน Chrome ปกติ ใช้เวลาไม่กี่นาที:
1. เปิดหน้าเว็บ แล้วกด `Cmd+Option+I` เพื่อเปิด DevTools
2. กด `Cmd+Shift+M` (device toolbar) แล้วตั้งขนาดเป็น 1440 × 900
3. กด `Cmd+Shift+P` พิมพ์ `Capture full size screenshot` แล้วกด Enter
4. ทำซ้ำทั้ง 5 หน้า แล้วตั้งชื่อไฟล์ `home-desktop.png`, `about-desktop.png`, `contact-desktop.png`, `guardian-and-other-desktop.png`, `act-dev-student-desktop.png`

## 6. ไฟล์ในโฟลเดอร์นี้

```
research/
├── summary.md                 ไฟล์นี้

├── lighthouse/
```
