# Book answer slides: rules (read CONTRACT.md first; every rule there still applies)

The owner photographed pages of the teacher's textbook. We make answer walkthroughs for those items.
- **Same items, same numbers, our own words and our own drawings.** Never paste a photo, never copy the book's sentences. Paraphrase each question in short Grade 7 English, keep the data needed to answer it, and redraw every table and chart in Style A (beautiful, animated).
- Every slide names its source so students can follow in the book: a chip like `Book p.200 · Unit 4 Test · Part 1 · Q7–8`.
- **Students present first.** Beat 0 shows the question(s), the data, and a place to work (w-input, mcq `.ch.ia[data-mcq]` without the right answer revealed, w-write, or a graph builder). Nothing of the answer is visible.
- **Then the thinking, one step per beat** (the owner wants the method, not only the answer):
  1. *Look* — what to read first (highlight the row, bar or key with an animated marker);
  2. *Think / calculate* — the working, one line per step (e.g. `75 ÷ 450 × 100 = 16.67%`);
  3. *Why* — one sentence of reasoning when it is a choice or a judgement;
  4. *Watch out* — only where students often slip (forgetting the key, an axis not from 0, the wrong base for a percentage).
  The final beat shows the answer clearly (`.ans`). 2–4 items per slide; group items that share one chart.
- If the book itself is ambiguous or seems wrong, say so kindly on the slide ("Book answer: … · Note: …") and in the notes.
- `<aside class="notes">`: the full working and the answer for every item, so the teacher can read it at a glance.
- Our widgets read the answers from data attributes in the page. That is fine for the keys deck (it is encrypted); in the public deck only put lesson questions, never test answers.
